Заголовки в SecurityHeaders
X-DNS-Prefetch-Control: off
Отключает предварительное разрешение DNS для ссылок на странице (браузер не будет заранее резолвить домены). По умолчанию часто включено для ускорения, но off тоже допустимо.

X-Frame-Options: DENY
Запрещает отображение страницы во фреймах (<frame>, <iframe>) — защита от clickjacking.

X-XSS-Protection: 1; mode=block
Включает встроенный фильтр XSS в браузерах (устаревшая функция, но полезна для старых браузеров); при обнаружении атаки страница блокируется.

X-Content-Type-Options: nosniff
Запрещает браузеру «угадывать» MIME-тип ресурса (MIME-sniffing), снижая риск атак, основанных на подмене типа содержимого.

Strict Transport Security: max-age=63072000; includeSubDomains; preload
(Опечатка: правильно Strict-Transport-Security) Заголовок HSTS заставляет браузер обращаться к сайту только по HTTPS в течение указанного времени (2 года), включая поддомены, и разрешает предзагрузку в список HSTS.

Content-Security-Policy: default-src 'self'
Политика безопасности контента: разрешает загрузку ресурсов (скрипты, стили, изображения и т.д.) только с того же источника, что и страница.

Referrer-Policy: no-referrer
Запрещает передачу HTTP-заголовка Referer при переходах с этой страницы, повышая конфиденциальность.

X-Powered-By: Django
Раскрывает технологию/фреймворк (здесь указано Django). Не рекомендуется для production, так как помогает злоумышленнику подобрать атаки.

Server: ""
Пытается скрыть информацию о серверном ПО (пустая строка может убрать заголовок, но нижележащий сервер иногда добавляет свой).

X-Permitted-Cross-Domain-Policies: none
Запрещает загрузку кросс-доменных политик (например, для Flash, PDF), предотвращая потенциальные утечки.

Cache-Control: no-store, no-cache, must-revalidate, max-age=0
Управление кешированием: no-store запрещает любое кеширование, no-cache требует проверки на сервере, must-revalidate обязывает перепроверять устаревшие копии, max-age=0 делает ответ немедленно устаревшим. Используется для конфиденциальных данных.

Cross-Origin-Resource-Policy: same-origin
Ограничивает доступ к ресурсу только с того же источника (защита от утечек через cross-origin запросы).

Cross-Origin-Opener-Policy: same-origin
Изолирует контекст окна: окно, открытое с этого источника, не будет иметь ссылки на открывающий контекст (защита от атак типа Spectre).

Cross-Origin-Embedder-Policy: require-corp
Требует, чтобы загружаемые кросс-доменные ресурсы явно разрешали включение через CORS или CORP, повышая изоляцию.

Permissions-Policy: geolocation=(self), microphone=()
Управляет доступом к функциям браузера: геолокация разрешена только для этого же источника, микрофон запрещён полностью.

Заголовки в Cosr (CORS)
Access-Control-Allow-Origin: (динамически, из списка разрешённых)
Указывает, какие источники (origin) имеют доступ к ресурсу. Устанавливается только если источник присутствует в allowedOrigins, иначе запрос отклоняется.

Access-Control-Allow-Headers: Content-Type, Authorization
Перечисляет заголовки, которые разрешено использовать в кросс-доменных запросах (применяется к предварительным запросам OPTIONS).

Access-Control-Expose-Headers: Authorization
Определяет, какие заголовки ответа могут быть доступны клиентскому JavaScript (кроме стандартных).

Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE
Указывает HTTP-методы, разрешённые для кросс-доменных запросов.

Access-Control-Allow-Credentials: true
Разрешает передачу учётных данных (cookies, авторизационные заголовки) при кросс-доменных запросах.

Access-Control-Max-Age: 3600
Задаёт время (в секундах), на которое результат предварительного запроса (OPTIONS) может кешироваться браузером.

Обработка preflight
При OPTIONS-запросе middleware сразу возвращает ответ без вызова следующего обработчика, так как это предварительный запрос CORS.
